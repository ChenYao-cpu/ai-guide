# 省赛痛点落地：网页端第一轮

依据用户提供的《景区AI数字人导览_48项调研与两周省赛优化报告》五类真实任务痛点（第13节），以及可信讲解、时间受限路线、无障碍、内容治理章节。仅修改网页及共享后端，不改变微信小程序布局。2026-10-12。

## 游客听不懂、回答偏题

导览问答提供简明、儿童、深入三种讲解方式；与中文/English独立组合。儿童模式默认短句、解释概念、提出安全的观察问题，不虚构人物对话、不让游客触摸或攀爬文物。16处景点具有本地儿童简介，模型不可用时仍能介绍；具体设施、票务、路线问题继续按所问主题回答，不能被儿童简介覆盖。

当前点位、明确提到的景点、追问和主题先消歧，再检索。无主题且无证据的问题直接说明知识缺口，不把流畅的模型输出当成知识。中英文采用相同中文事实档案及专名映射。外语ASR口音、海外网络、人工术语审核仍需独立现场测试。

## 回答有资料，也要能核对

默认本地检索器在景点与主题过滤之后执行BM25与字符TF-IDF，使用RRF(k=60)合并两份各20项候选，选择最多5片段。它是词法混合检索，没有声称已实现密集语义嵌入、GPU重排或知识图谱。

每个检索片段保存原文、文档名、主题、稳定片段ID和SHA-256内容版本；随回答持久化，刷新后仍可展开核对。已有官方来源链接继续保留。片段来自整理后的档案，不能称为官方网站逐字原文。

生成回答先检查资料未出现的阿拉伯数字数值，再执行一次模型辅助证据核对（12秒调用超时）。核对需覆盖回答全部段落，每段给出资料ID和逐字引用；代码验证引用确实包含于指定原文、段落未遗漏或重复。缺证、引用伪造或核对服务失败时，回退本地档案。按回答与证据内容哈希缓存最多128项核对结果，证据变化使缓存失效。

这是辅助核对：相同模型仍可能错误判断蕴含关系，数字检查也不能判断“数字用错对象”或中文数字。界面没有显示“100%正确”“人工认证”或虚构置信度。后续必须以独立题集和人工标注评估事实正确率、漏证率、拒答率、时延；当前自动回归用例数不是这些指标。

## 时间有限、老人孩子走不完

个性化规划新增离园区域、排队预留、临时避开一个景点。修改条件后提示重新生成；生成按钮才更新推荐，不静默替换行程。AI推荐和直接生成使用相同约束。

预算包括停留、景点之间步行、休息、末站至出口附近锚点的步行，以及额外5分钟进出预留、游客填写的排队预留。离园与预留在每次插入候选时就计算，不能先塞满景点再加时间。轻松/亲子模式降低步行速度、排除已标注多台阶景点，并按包含离园的时间增加休息预留。

出口附近锚点分别为仁寿殿、苏州街、铜牛，不是测绘过的门口。路网距离、停留、步速均为估算。北宫门附近也不能因此称为轮椅可行通道。未选择离园时明确提示“不计算离园”。预留不是实时排队预测，临时避开来自游客选择而非实时封闭通知。目前没有在游览中自动重排行程，没有实时客流、票务、闭园或船渡接口，不保证实际准时或全局最优。

## 小字、纯语音、厕所和休息点找不到

网页导览提供大字阅读（正文20px）、仅文字、慢速语音（0.8倍），保留字幕式文字、键盘原生控件、焦点提示与对话读屏提示。1440×900桌面页面保持一屏；聊天内容在内部滚动，左侧数字人占据完整展示区域。大字阅读和仅文字在本机保存。

星云当前接入未提供逐轮语速设置。慢速模式播放Edge合成语音，此时不声称星云口型同步；仅文字完全停止播放，后端也跳过语音合成和数字人视频/动作生成。星云正常模式继续按原SDK驱动。听障可阅读文字，不能称为已实现自由手语或可靠避障。

设施或通行资料缺失时，回答准确指出未知项，并提供[颐和园官方设施与无障碍地图](https://www.summerpalace.net.cn/guide_map.html)和官网公布的咨询电话010-62860608（2026-10-12核对）。拨号按钮只是打开拨号程序，不是已接通或已通知工作人员。未核实最近厕所、休息点坐标，不提供虚假的精确方向或距离。

## 管理者如何维护内容

上传PDF、Word、TXT、Markdown后进入待审核，不立刻影响问答；服务端限制20MB。预览提取正文（最多12000字，超过时可打开完整文档）与完整SHA-256版本。审核说明至少3字；发布、驳回、撤回均留存审核人、时间、说明、前后状态和内容版本。

发布前验证预览版本与磁盘文件哈希，先准备新的完整检索快照；准备失败则文档状态、审核历史和当前索引保持原样。数据库提交后替换索引。撤回/删除同步移除公开索引中的文档。修改操作通过进程内锁串行执行。私有管理员的本地索引重建不会覆盖景区公开游客索引。

原有“已收录”文档保留，界面明确“无本次人工审核记录”，没有将历史资料自动冒充审核通过。审核可由上传者自己完成，不是双人审批制度。当前是单进程本地快照；多进程部署需集中索引版本/失效通知与分布式锁。这里尚未替代法务授权审核、运营值守或大规模容量测试。

后端：`.venv/Scripts/python.exe -m unittest discover -s scripts/tests -p test_*.py`。

前端：在frontend执行 `node node_modules/vitest/vitest.mjs run src/views/visitor/__tests__/TourInteractionView.spec.ts src/components/__tests__/AvatarLoading.spec.ts`，以及 `node node_modules/vite/bin/vite.js build`。

真实接口：`.venv/Scripts/python.exe scripts/verify_pain_point_support.py`。脚本只创建标记为验收的临时文档与会话，验证发布/撤回、错误版本拒绝、预算、临时避开、儿童/深入/英文/设施缺口/未知问题/慢速音频，结束自己的会话，删除自己的临时文档。原始结果写入忽略目录 `work_dirs/pain-point-acceptance.json`，不记录密钥或登录Token。

这轮回归49项后端、17项导览前端测试通过，生产构建和全项目类型检查通过。修复了原有直播组件defineModel数组/对象默认值工厂，以及已有默认值的optionList可选类型声明；没有改变直播业务流程。

真实样本：120分钟、东侧出发、北侧离园、20分钟排队预留，选昆明湖与石舫，预算113分钟=停留50+景点间步行20+休息7+离园16+预留20。它是可复算估算，不是游客现场轨迹测量。
