# App 1.3.4：数字人兼容、半身横向展示与播放链路

继续以 `84e5268166f21fea5764b482d24aac5420372a67` 为基准，保留 1.3.3 的景点选择弹框和简化聊天界面，仅修复 App 数字人相关实现。

## 已定位的原因

- 1.3.3 沿用上游的在线 `latest` SDK，绕过了包内经过 Android 兼容处理的版本，重新引入必须支持软解码的限制。
- 导览的云端素材是 1080×1920 全身画布；恢复全身缩放和固定左移不能实现稳定居中的半身展示。
- 连接时父页面把待播讲解放入连接 payload，连接成功后又发送同一段讲解，组件也会播放首次 payload，存在重复打断。
- 快速重连时，后续请求可能在旧 SDK 销毁完成前创建实例。纯语音入口也会创建隐藏的视频解码和渲染负载。
- 原错误处理把 WebGL 已恢复、网络已恢复等通知也作为致命错误，可能把 SDK 自身的恢复流程再次中断。

## 修复

- 两个入口统一使用随包固定的兼容 SDK，并明确优先硬件解码；真实解码失败仍会报错。关闭 SDK 调试日志和调试器。
- 导览采用横向宽画面，将全身源画布的 y=10%..58% 区域居中展示。仅由 CSS 等比例裁切，不逐帧测量 DOM，不修改 WebGL 内部画布分辨率及嘴型投影。
- SDK 行走偏移交给空代理处理，避免为一个固定机位的半身画面逐帧改写 DOM transform。
- 连接时移交待播讲解的所有权，确保首次讲解只发送一次；销毁操作串行化，丢弃已经过时的连接请求。
- AI 小导游使用 SDK 的 `audioOnlyMode`，停止解码和渲染不可见的数字人视频。
- 区分恢复通知和真正错误，允许 SDK 完成自身恢复。画面帧率最多每 5 秒回传一次，仅存本机最近一次不含凭据的诊断数据 `zhiyou.avatar.last-performance`。
- 打包脚本强制执行数字人发布检查。在线 SDK、软解码回退、隐藏视频渲染、左移或半身样式丢失、SDK 校验值改变时停止打包。App AGENTS.md 同时记录这些要求，更新基准不能直接回退。

## 验证范围

- 25 项 Node 检查通过，覆盖 SDK 加载、真实解码结果必须成功的规则、恢复通知、异步销毁、重复讲解、帧率回传节流、发布检查的反向用例，以及聊天回归。
- 4 种视口、3 种 SDK 对齐/偏移配置共 12 个布局场景通过，检查头部可见、下半身被裁切、比例和居中。该测试的画布内容为模拟。
- 真实云端检查创建并关闭了自己的测试导览和数字人会话。桌面 Chrome 实际解出视频帧并播报，14 秒讲解检查后段当前与平均帧率约 24 FPS，末段累计丢帧计数保持 12。截图确认真实云端形象为居中半身。
- 桌面云端检查不能证明 Android 真机同样流畅；未连接真机时不会宣称所有手机的卡顿彻底消失。若真机仍有问题，可结合最近一次画面帧率继续定位。
