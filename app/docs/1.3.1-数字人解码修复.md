# App 1.3.1：数字人解码兼容

基准保持 main `9ec7decfa423e46fe05ebacff83cdd5d1cd9abe1`，保留已有路线与用时、扩大地图及 LZX 景区图片。本次仅修复 App 数字人的安卓解码兼容，不修改 Web 或后端。

## 原因与修改

1.3.0 使用基准代码中的在线 SDK 加载方式，遗漏旧版已采用的 Android 兼容补丁。SDK 会在支持硬件视频解码时仍要求支持软件解码，导致设备出现“不支持软解码”提示。

导览和聊天语音都改用随包发布的固定 2.4.1 兼容 SDK，并指定 `hardwareAcceleration: 'prefer-hardware'`。兼容版取消 Android 必须支持软解码的前置要求，并尊重调用方选择的解码模式；仍需实际成功解出视频帧，真实解码失败仍会报错。加载失败可以重试，不依赖远程 `latest` 文件。

## 验证边界

- 修复前新增回归检查，两个 App 数字人入口均因缺少硬件解码选项失败；补丁后通过。
- `node --test app/tests/*.test.cjs`：24 项通过，覆盖 SDK 加载、模拟解码成功和失败、两个数字人入口，以及原有路线和图片回归。
- 模拟解码和编译检查不能替代 Android 真机验证；设备安装后需重新进入导览测试。
- 数字人仍依赖原有后端会话、网络和设备 WebView 的实际解码能力。
